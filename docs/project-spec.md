# プロジェクト概要

Slug-Free Permalinks は、通常投稿のパーマリンクをWordPress標準設定で管理し、選択したカスタム投稿タイプと公開タクソノミーにIDベースURLを適用するプラグインです。

## 公開向けプロダクト情報

### 一言でいうと

スラッグ管理を減らしたいWordPress管理者向けに、通常投稿は標準機能、カスタム投稿タイプ・分類はIDベースURLで管理するプラグイン。

### キャッチコピー

- 課題解決型: 投稿のたびにスラッグを考える作業を、URL 設計から減らす。
- 得られる結果型: タイトルや言語に左右されにくい、ID ベースの URL へ。
- 利用シーン型: 新しい WordPress サイトのパーマリンク方針を決めるときに。

### 誰のどんな困りごとを解決するか

最優先の利用者は、新規サイトまたはパーマリンク方針を検討中の WordPress 管理者です。投稿やカテゴリー、タグを公開するたびにスラッグを決めたり、タイトル変更後に URL とタイトルのずれを気にしたりする運用を減らします。マルチバイト文字が URL エンコードで長く読みにくくなる場面にも対応します。

### 提供する価値

- 投稿・分類の URL をタイトルや言語固有のスラッグに依存しない ID ベース形式へ揃えられます。
- どの公開投稿タイプ・公開タクソノミーに適用するかを選べるため、対象外の URL は従来どおりに保てます。
- タイトルを変更しても URL の ID は変わらないため、URL と表示タイトルを別々に管理できます。

### 代表機能

- 公開カスタム投稿タイプを個別選択 → 選んだカスタム投稿タイプをIDベースURLへ切り替えられます。
- 公開タクソノミーを個別選択 → 選んだカテゴリーやタグなどだけを同じ形式にできます。
- 登録済み rewrite slug を使用 → カスタム投稿タイプやタクソノミーの ID ベース URL にも登録済みの rewrite slug を使います。
- スラッシュ形式・ハイフン形式の選択 → カスタム投稿タイプなどで`/book/123/`または`/book-123/`を選べます。
- 旧スラッグ URL の任意リダイレクト → WordPress が解決できる旧 URL を、現在の ID ベース URL へ転送できます。
- 通常投稿の標準設定 → WordPressの現在のパーマリンク構造を表示し、設定画面へ誘導します。旧方式の利用者に限り明示的な移行操作を表示し、WordPress標準の`%post_id%`構造へ移行して通常投稿をプラグイン対象から外します。
- ID 形式の切り替えリダイレクト → 旧 URL リダイレクト有効時、選択していない ID 形式の URL も現在の形式へ転送します。
- 他CMSからの移行 → 任意機能を有効にすると、投稿の既存カスタムフィールド`legacy_id`をURL識別子に使い、未設定記事は投稿ID（初期値）またはスラッグへフォールバックします。
- Polylang の言語 URL を維持 → Polylang が実際に公開している言語ホーム URL を基準に、ID ベース URL と rewrite rule を構成します。

### 選ばれる理由

- 通常投稿はWordPress標準設定に委ね、選んだカスタム投稿タイプとタクソノミーだけにプラグインのID形式を適用します。
- 旧 URL の転送では、404 ごとのスラッグ推測を行わず、WordPress がすでに解決できるリクエストだけを対象にします。
- URL 形式を変更することに集中したプラグインで、コンテンツ機能やフロントエンド UI は追加しません。

### 利用シーン

- 新しい WordPress サイトで、スラッグを運用ルールに含めず URL 方針を決めたいとき。
- カスタム投稿タイプやタクソノミーを使い、対象ごとに ID ベース URL を設定したいとき。
- Polylang の言語 URL を使いながら、対象コンテンツの URL を ID 形式にしたいとき。

### 制約・対象外

- 固定ページは対象外です。
- 選択した投稿タイプまたはタクソノミーの登録済み rewrite slug が同じ場合、設定保存を拒否して ID ベースのルート競合を防ぎます。
- Polylang の言語ホーム URL にパス接頭辞がある場合、その実在する接頭辞だけを ID ベースルートとして登録します。任意のパス接頭辞は受け付けません。
- 既存のスラッグ URL を多く公開しているサイトでは、有効化前に被リンク、検索流入、SNS 共有、編集フローへの影響を確認してください。
- 旧 URL のリダイレクトは任意設定であり、WordPress が解決できない 404 URL を推測して転送する機能はありません。
- 通常投稿の標準パーマリンク構造とWordPress設定画面へのリンクを常時表示します。旧方式の通常投稿が残っている場合は、現在のID URLと等価な移行先構造と移行ボタンを表示します。移行までは旧URL形式を保持し、CPT向けの形式切替を制限します。移行操作だけが標準設定を変更し、通常投稿をプラグイン対象から外します。
- カスタム投稿タイプとタクソノミーは WordPress 標準の投稿パーマリンク設定だけでは引き継げないため、登録元の rewrite 設定を別途確認します。

## 移行元の識別子

- 明示的に有効化した場合のみ、通常投稿の`%legacy_id%`タグと選択済みCPTのIDパスで投稿メタ`legacy_id`を参照する。`permalink_structure`はWordPress標準を正本とする。
- 投稿メタの作成・編集・インポート・一括監査は担当しない。投稿編集画面へ独自入力欄を追加しない。管理画面には簡潔な説明とフォールバックの選択のみ表示する。
- 通常投稿は`%legacy_id%`を標準の構造入力欄へ挿入して使う。CPTは登録済みrewrite slugの下に識別子を配置する。固定ページ・タクソノミーには適用しない。
- 識別子はASCII英数字・`-`・`_`を許可する。空値・欠損時は投稿IDまたは投稿スラッグ。利用できない形式は投稿IDを使用する。異なる投稿に同じ識別子が該当した場合は解決しない。
- 旧URLのパス構造を再現できることが前提。DB検索は対象のlegacy URLに限り行う。WordPress投稿IDやスラッグとの衝突は誤配信を防ぐため404にする。
- `legacy_id`がONでも旧スラッグURLの301（設定ON時）を維持する。既存CPTスラッグを安全に特定できる場合のみ正規URLへ転送し、識別子が衝突するときは404にする。
- `%legacy_id%`はWordPress標準タグではないため、プラグイン無効化後は解決できない。無効化前に標準タグへの移行または転送が必要。
- **サイト公開前に**200/301/404、既存URL、サブディレクトリ、Polylangを実HTTPで確認する。

## 対応環境

- 最低対応環境はWordPress 6.4以上、PHP 8.2以上。`plugin-meta.json`を正本とする。
- 旧バージョン専用の互換処理は、明示された利用要件がない限り追加しない。
- `testedUpTo`は動作確認済みのWordPress上限であり、最低対応バージョンとは区別する。

## 設定の読み取りと正規化

- 公開リクエストでの設定読み取りは副作用を持たず、パーマリンク解決やフィルター実行だけではオプションを書き換えません。
- `get_settings()` は保存値を現在のリクエスト用に正規化してメモリ内キャッシュへ保持しますが、データベースへ保存しません。
- 保存済みの配列が旧形式または不正な値を含む場合は、管理画面側の `admin_init` でのみ正規化し、値が変わるときだけ保存します。
- 保存値が配列でない場合は既定値として読み取りますが、正規化処理からは書き戻しません。

## v2.0の設定画面

- 「通常投稿」ではWordPress標準のパーマリンク構造を1つの編集可能な入力欄で扱う。プリセットは欄全体を更新し、タグボタンはカーソル位置へ挿入する。保存先は標準の`permalink_structure`のみで、独自の通常投稿設定は追加しない。
- v1.x由来の通常投稿設定が残る場合は旧形式と等価な`%post_id%`構造を同じ欄に表示する。移行操作はその構造と一致する場合のみ許可し、既存URLを維持する。移行後に構造を自由に編集・保存できる。
- 「カスタム投稿タイプとタクソノミー」では対象選択、ID URL形式、任意の旧URLリダイレクトを設定する。通常投稿は選択項目に含めない。
- 未移行の通常投稿がある間は共通ID形式の変更を制限し、通常投稿の旧URLを保持する。保存済みの通常投稿設定は明示的な移行まで維持する。
- 移行後は通常投稿をプラグイン側から再び選択できない。WordPress標準設定はプラグイン無効化時にも戻さない。
